## Deviation worth naming

The bucket text asks the panel to project rule checks "from the canonical result payload". The payload
carries only `valid` and `violationCodes`, so PASS/WARNING/FAIL rows cannot be read from it without
either inventing statuses or extending the payload shape. Extending it would move
`fingerprintGenerationResult`, the canonical diagnostics fingerprint and the Stage 0 regression
baseline — a domain-evidence change inside a UI bucket.

Instead the panel re-runs the authoritative evaluator
(`prepareRuleContext` + `evaluatePlanlabCoreRules`) for the three selected layouts and memoises the
result per `(layout, project snapshot)`. The payload, worker protocol, solver, scoring and canonical
serialization are untouched, and the displayed verdict is the validator's own.

## Open finding: `baselineMatch` is false for provenance reasons, not for drift

The recorded baseline in `artifacts/planlab/milestone-3/benchmark-baselines/full.json` stores
`benchmarkInputFingerprint = 9d0bcfc3…`. Recomputing the manifest from committed blobs gives
`44369852…`, from today's working tree `0a0bac80…`, and **no commit in the last 30 matches the
recorded value** (checked by hashing each commit's blobs for the same file list).

The manifest hashes raw bytes of `package.json`, `scripts/benchmark-stage0.mjs` and every
`src/domain` module (`benchmarkInputManifest()`), and `core.autocrlf=true` on this machine rewrites
line endings on checkout — 15 of 26 manifest files already differ from their committed blobs. So the
gate compares a working-tree byte hash against a hash recorded from a different checkout state.

This bucket changes no manifest file (only `src/app`, `test`, `scripts/capture-ui.mjs` and docs), so it
cannot have caused the mismatch. Recommended follow-up (not done here, because it re-records benchmark
evidence): hash normalised content (or `git` blob content) in `benchmarkInputManifest()`, or pin
line endings with a `.gitattributes`, then re-record the baseline once.
