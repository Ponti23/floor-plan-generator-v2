**Status:** complete. **Executor:** orchestrator (`/root`). **Date:** 2026-09-15.

## Changes

1. `src/worker/controller.ts` — `GenerationState` now exposes `startedAt` and `watchdogMs`. Every
   terminal path (result, cancel, watchdog, worker error) clears `startedAt` through `finish()`, so the
   UI can never show a stopped clock as if a run were still going.
2. `src/app/main.ts`
   - `progressReadout()` — deterministic counters plus elapsed time against the watchdog budget.
   - `syncProgressTicker()` — a 250 ms ticker that rewrites only the two status text nodes. A full
     re-render four times a second would drop focus and scroll position mid-edit.
   - Stale banner with a working Regenerate action.
   - Generate is disabled while a run is in flight; Cancel is enabled only then.
   - `startVariations()` — the UI_ARCHITECTURE "new variations" behaviour (Retry keeps the seed; this
     explicitly moves it) without adding a fourth primary button.
   - Out-of-scope toolbar controls (`New`, `Grid`, `Measurements`, `Settings`) are now genuinely
     disabled shell controls with an explanatory `title`, instead of buttons that look live and do
     nothing.
3. `src/app/editor-state.ts` — `bumpVariationSeed()`; deterministic (`canonical-0 → canonical-1`,
   `seed → seed-2 → seed-3`), never random.
4. `src/app/styles.css` — select focus-visible, disabled toolbar treatment, banner and text-action
   layout. Status stays non-colour-only: every chip, banner and dot carries text.
5. `src/app/presentation-copy.ts` — new structural strings: `actions.newVariations`,
   `status.progressWatchdog`, `status.staleAction`, `toolbar.disabledReason`.
6. `scripts/capture-ui.mjs` — `--pre`, `--post` and `--immediate` so the fidelity loop can capture
   generating, stale and post-edit states, not just a settled run.

## Notes and deviations

- `budgetExceeded` is also the watchdog outcome (the controller maps a wedged worker onto it). The
  copy states the search budget was reached, which is accurate for both paths; the UI does not claim
  which one fired.
- "New variations" is a secondary text action next to "Discard edits" rather than a fourth control in
  the primary button row, to keep the approved mockup composition.
- Keyboard: every new control is a real `button` in DOM order (brief → canvas → analysis), selects now
  show the same focus ring as inputs, and disabled controls leave the tab order instead of accepting
  focus and doing nothing.
