# Bucket 5.6 — Stage 0 baseline provenance fix

**Status:** complete. **Executor:** orchestrator (`/root`). **Date:** 2026-09-15.
**Trigger:** found while verifying 5.3. `npm run benchmark:stage0:check` passed every substantive gate
line but reported `baselineMatch: false`.

## The defect

`benchmarkInputManifest()` in `scripts/benchmark-stage0.mjs` hashed the **raw bytes** of
`package.json`, the runner, and every `src/domain` module. With `core.autocrlf=true` on Windows, a
working tree holds CRLF bytes for files that are stored as LF in Git, so the fingerprint identified
the *checkout*, not the source.

Evidence that it was provenance and not drift:

1. The recorded baseline's fingerprint (`9d0bcfc3…`) matched **no committed tree** in the last 30
   commits (each commit's blobs were hashed for the same file list).
2. Today's working tree produced `0a0bac80…` and the committed blobs produced `44369852…`; 15 of 26
   manifest files differed from their blobs purely by line endings.
3. 5.3 changed no manifest file at all (only `src/app`, `test`, `scripts/capture-ui.mjs` and docs).

## The fix

`hashSourceFile()` reads each manifest file as UTF-8, normalises CRLF to LF, and hashes that. The
fingerprint now describes the source content and is identical in an LF checkout, a CRLF checkout and a
CI clone. The recorded baseline was then re-recorded with `--record-baseline`.

## Proof that re-recording hid no drift

The pre-existing baseline was copied to a temp directory before the re-record. Comparing the two
baselines field by field:

| Field | Result |
|---|---|
| `benchmarkInputFingerprint` | changed by design (`9d0bcfc3…` → `b85af1b6…`) |
| `canonical` (all per-seed output, layout, selection and evidence hashes) | **identical** |
| `impossibleFixtures` | **identical** |
| `historicalStage0Baseline` | **identical** |
| `budget`, `seeds`, versions, `searchPolicy` | **identical** |

So every recorded verdict and every canonical hash is unchanged; only the provenance value moved.

## Verification after the fix

- `npm run benchmark:stage0:check` — **`pass: true`, `baselineMatch: true`**, median **1815.5 ms**,
  p95 **1845.0 ms** (measured while an independent review agent was running on the same machine, so
  the real quiet-machine figure is at or below this). Every gate line true:
  `threeValidLayoutsPerSeed`, `diversityThreshold`, `determinism`, `expansionBudget`,
  `budgetDeterminism`, `timingGateApplied`, `medianRuntime`, `p95Runtime`, `impossibleFixtures`.
- The fingerprint recomputes to `b85af1b6…` from the committed content independently of the checkout's
  line endings.
- `npm run diagnostics:canonical -- --check` — clean at `sha256:8efe5b5e…`.

## Residual note

The timing gate still sits about 9% below the 2000 ms threshold on a loaded machine and expansions run
at roughly 15.4k of the 20k cap. The margin is real but thin; any future generator change must
re-measure on a quiet machine before it is called safe. A `.gitattributes` with `eol=lf` would remove
the underlying checkout difference entirely and is worth doing when a bulk renormalisation commit is
acceptable.
