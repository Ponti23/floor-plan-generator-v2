## Defects found and fixed

1. **Stored results were not linked to the brief they belonged to.**
   `restoreStoredResult()` only required that *a* brief loaded successfully. After
   generate → edit/commit → reload, the old result could be restored as if it answered the new
   brief. `StoredResultDocument` now carries `briefFingerprint`, written as
   `fingerprintNormalizedProject(editor.committedProject)`, and restore discards the result unless
   the fingerprint matches.

2. **A malformed stored result could pass `readStoredResult` and crash `controller.restore()`.**
   `readStoredResult` only checked that `layouts` and `candidates` were arrays. A document with a
   matching version block but no `ok`/`selection` reached `payload.selection.complete` and threw.
   The reader now validates the payload structure, and `restoreStoredResult()` additionally performs
   a read-only projection smoke test before calling `controller.restore()`.

3. **A real payload-version bump was classified as corrupt instead of outdated.**
   Because structural validation required the current payload version, a future build's
   `planlab-generation-result-payload-2` document was deleted as corrupt and the user never saw the
   “different build” notice. Version skew is now classified before strict payload validation, so a
   payload-version bump surfaces `outdated`.

4. **Reset left boot-time storage and outdated-result notices visible.**
   `storageNotice` and `resultsOutdated` were module state set at boot and never cleared by
   `performReset()`, so after a reset the brief pane could still claim the old saved project was
   unreadable or that previous layouts had been discarded. Both are cleared on reset.

5. **A failed result write was marked persisted.**
   `persistResultIfCurrent()` set `lastPersistedPayload = payload` before `setItem`, so a
   quota/denied write was never retried. It now records the payload as persisted only after the
   write succeeds.

6. **A faulty registered migration could write an unloadable document.**
   `migrate()` rewrote after all steps succeeded but did not validate the final document, so a bad
   migration could produce a value the next boot classified as corrupt. The final migrated document
   is now passed through the same `parseDocument()` reader before the rewrite.

7. **Retry generation did not force a brief save.**
   `Generate` flushed the brief before starting, but `Retry` only scheduled the debounce. A very
   fast run could persist a result before the brief it depended on. Retry now forces the same flush.

## Open findings

1. **`clear()` failure honesty.** `performReset()` calls `projectStore.clear()` and then always
   sets save status to `saved`. If storage enumerates but refuses `removeItem`, the UI can claim a
   successful reset even though PlanLab-owned keys remain. The store already reports exactly what it
   removed; the UI does not consume that result. Low severity, no normal-browser reproduction.

2. **No registered real migrations.** The 6.2 mechanism is genuine and now validates its final
   document, but no real migration is registered because only store version 1 has ever existed.
   That is correct YAGNI and is recorded in `6.2-migrations.md`; the first real format change must
   supply its own migration.

3. **Result-store format change is discard-only.** A pre-fix stored result without
   `briefFingerprint` is now classified corrupt and deleted on load. Safe and honest, but it means
   the first result-format change silently loses that cached result rather than migrating it.

4. **Reset verification not asserted in unit tests.** Reset’s controller behavior is tested, and
   prefix-scoped `clear()` is tested, but the main-thread reset wiring is verified only by the
   existing `6.4-reset-flow` browser capture.

**Verdict: PASS.** Stage 6 closes on this review plus two follow-ups below.

What I verified myself rather than accepting from the review:

- `npm test` **199 passing**, `npm run typecheck` clean, `npm run build` clean,
  `npm run diagnostics:canonical -- --check` clean at `sha256:8efe5b5e…` — the domain is untouched by
  all of Stage 6.
- The seven fixes are real in the diff, and the two that matter most are now covered by evidence the
  review could not produce: the brief-fingerprint link (a result can no longer be restored against a
  different brief) and the corrupt-result classification.

**Follow-up 1 — open finding 1 closed, and it exposed a worse bug.** `performReset()` now consumes
what the store actually removed: it re-reads `ownedKeys()` after `clear()` and reports
`resetIncomplete` (plus a failed save state) if anything survived, instead of always claiming
success. Injecting a storage that throws on `removeItem` produced the notice and left
`planlab:v1:junk` in place, as intended.

Fixing that surfaced a defect neither review saw: **the save-status label never updated.**
`renderSaveStatus()` looked for `[data-save-status]` and fell back to "the second span", but the
toolbar template renders the label as a bare text node, so the code silently did nothing — the
indicator read `Saved locally` even while saving, and even when a write had failed. It now rewrites
the text node directly. Verified in the browser: editing a field shows `Saving…`; a store that
refuses the reset's removal shows `Local save failed`.

**Follow-up 2 — the evidence gap in the review's own record is closed.** The review noted it could
not plant corrupt state, reload, and then interact, because the harness applied `--post` before
`--reload`. The harness now supports `--post-reload`, so that sequence is captured:
`6.6-reset-clears-notice.png/.json` shows a corrupt-brief notice present before Reset, and
`noticeAfter: null` with `keysAfter: []` after it — which also verifies the review's fix 4 with a
browser rather than by reading.

**Carried forward, explicitly not defects:** no real migration is registered (nothing to migrate;
the mechanism is tested with injected steps and now validates its output before rewriting), and a
result-store format change discards rather than migrates a cached result — safe and honest, and the
first format change owns it.
