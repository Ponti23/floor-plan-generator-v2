# Bucket 7.3 — rendering and performance profile

**Status:** complete. **Executor:** orchestrator (`/root`). **Date:** 2026-09-15.
All numbers below were measured on this machine **while an independent review agent was running**, so
they are pessimistic. The Stage 0 gate figure must be re-taken on a quiet machine before it is treated
as the reference (see "What still needs a quiet machine").

## Workspace, in a real browser, on the production build

Served with `npm run preview` (built `dist/`, worker loaded from its hashed production asset), measured
by `scripts/capture-ui.mjs` — three runs:

| Measurement | Run 1 | Run 2 | Run 3 |
|---|---|---|---|
| Click Generate → three option cards rendered | 1,857 ms | 1,853 ms | 1,877 ms |
| DOMContentLoaded | 295 ms | 96 ms | 155 ms |
| load event | 351 ms | 165 ms | 234 ms |
| first contentful paint | 542 ms | 363 ms | 459 ms |

The generate figure is dominated by the solver, not by the interface: the worker-only benchmark
measures a **median 178.4 ms** for the same canonical brief with the default budget, so roughly 1.6–1.7 s
of the browser figure is the full generation budget on a loaded machine. Note the browser figure also
includes the worker's postMessage of the trimmed payload and the first render of three cards.

## Projection costs (Node, same process, 20 iterations unless noted)

| Projection | Cost |
|---|---|
| Plan SVG for the selected layout (`projectPlanSvg`) | **0.052 ms** |
| Three option thumbnails (`projectThumbnailSvg`) | **0.050 ms** |
| Layout facts + full rule pipeline for one layout (memoised in the app) | **0.215 ms** |
| Metric rows + category rows for the panel | **0.008 ms** |

Rendering is not a risk. The one genuinely non-trivial cost the UI can incur is the
facts-plus-rules pass behind the analysis panel (0.215 ms), and that is memoised per
`(layout, project snapshot)`, so it repeats only when the selected layout or the brief changes.

## Storage cost

Per generation the app writes the trimmed result document: **35,967 bytes** (3,403,986 bytes of
canonical payload projected down to the three selected layouts plus their scorecards) and, on the
first save, a **2,579-byte** brief. Both are well inside a browser's storage budget, and neither is on
the interaction path — the write happens after the result is rendered.

## Stage 0 gate on a quiet machine (the number this bucket owed)

Re-run after every review agent had stopped, on the same machine:

```
median 1,856.8 ms   (gate < 2,000 ms)   PASS
p95    1,951.3 ms   (gate < 4,000 ms)   PASS
baselineMatch: true,  pass: true
```

Every substantive gate line was true: three valid layouts per seed, diversity threshold, determinism,
expansion budget, budget determinism, both timing lines, and impossible fixtures. The earlier loaded
measurements in this session were 1,815–1,919 ms median, so load moved the figure by roughly 2–3%
rather than by the margin that matters.

**The margin is real but thin — about 7% against the median gate — and it is unchanged by any work in
Milestones 5–7, none of which touched the solver.** Any future change to the generator's search must
re-measure here before it is called safe.

### A baseline footgun fixed in the same pass

Adding the `preview` npm script in bucket 7.2 moved `baselineMatch` to `false`, because the benchmark
input manifest hashed `package.json` byte-for-byte. That is the second time a change that cannot
affect a single layout forced a baseline re-record. The manifest now hashes only the fields that can
affect results — dependencies, dev/optional/peer dependencies, `engines`, `type`, `packageManager`,
with sorted keys — so script additions no longer move it. Verified directly: with a script added in
memory the fingerprint is unchanged, and with a dependency added it still moves.

## Conclusion

The workspace meets its targets with room to spare: the interface costs fractions of a millisecond
per projection, first paint is under 0.6 s, and end-to-end generation is the solver's own budget.
The only open performance risk remains the solver's Stage 0 median margin, which is unchanged by this
milestone.
