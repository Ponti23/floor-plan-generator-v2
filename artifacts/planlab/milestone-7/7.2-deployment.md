# Bucket 7.2 — production deployment configuration and support limitations

**Status:** complete. **Executor:** orchestrator (`/root`). **Date:** 2026-09-15.

## What shipped

- **`vercel.json`** — framework `vite`, build `npm run build`, output `dist`, plus three static-host
  hygiene headers (`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
  `Referrer-Policy: strict-origin-when-cross-origin`). No redirects, no rewrites, no server runtime:
  the app is one page plus a hashed worker asset.
  - A Content-Security-Policy was deliberately **not** added. The plan viewport uses inline `style`
    attributes for pattern fills and bar widths, so a CSP would need `style-src 'unsafe-inline'`, and
    a wrong policy would break the deployed app in a way this machine cannot reproduce (the harness
    serves without headers). It belongs with a deploy that can be verified end to end.
- **`npm run preview`** — added to `package.json`; the production-path check below needs it, and the
  README documents it.
- **`README.md`** — what the tool is, how to run and test it, how it deploys, and a
  **Limitations** section that carries the approved conceptual-use notice and the five prohibited
  claims from the 5.0 gate verbatim in intent: no compliance/certification/approval, no
  construction-document or cost suitability, no accessibility compliance, no
  "architect-approved"/"guaranteed"/"optimal"/"buildable", and no score-as-regulatory-assessment.
  It also states, plainly, that one project is stored in this browser only, that the wider candidate
  pool is not saved, and that the build is desktop-first.
