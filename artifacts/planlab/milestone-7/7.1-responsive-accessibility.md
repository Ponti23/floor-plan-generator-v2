# Bucket 7.1 — responsive panel collapse and accessibility sweep

**Status:** complete. **Executor:** orchestrator (`/root`). **Date:** 2026-09-15.

## Responsive behaviour

- **Desktop is untouched.** At 1536 px the two pane toggles are `display: none`, the panes measure
  310 / 841 / 385 px and the document is exactly 1536 px wide with no scrollbar — the mockup
  composition, measured after the change.
- **Below 1180 px the panes can be folded.** Two toolbar toggles (`Brief`, `Analysis`) appear, each a
  real `button` with `aria-pressed` and `aria-controls`. Measured at a 1000 × 900 viewport: the plan
  is 390 px with both panes open, **615 px** with the brief folded, and **1000 px** with both folded.
  Folding never removes the only way back: the toggle stays in the toolbar and reports its state.
- `body` keeps a minimum width, so a narrow window scrolls instead of crushing the plan into a
  sliver — the behaviour the fidelity brief asks for at the responsive boundary.

```

```

Per state:

- **complete** — 0 unnamed controls, 0 duplicate ids.
- **generating** — 2 polite live regions carrying the progress readout, Generate disabled, 9 controls
  correctly disabled and out of the tab order.
- **reset confirmation** — `role="alertdialog"` labelled "Reset project?", both controls named.
- **focus management (fixed here):** opening the confirmation previously left focus on `<body>`.
  It now moves to **Keep project** — the safe choice, so a keyboard user cannot confirm a destructive
  reset with a second Enter — and cancelling returns focus to the reset control. Verified:
  `inDialog: "reset-cancel"`, `afterCancel: "reset-project"`.

## Also fixed here

The older narrow-width rule `.\toolbar-right .toolbar-button:nth-child(2) { display: none }` was
silently hiding the new Brief toggle, so only one of the two toggles appeared. The pane toggles now
override it explicitly, verified by reading computed styles at 1000 px.
